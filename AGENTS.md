# Architecture rules
- Support conversation rules live in src/server/AGENTS.md.
- PC card printing adapts the native same-origin array manifest and embeds original single-card PDF pages without rasterization; eligibility is rechecked before output. Why: preserves embedded fonts and approved layouts while blocking retired presets without new permissions.
- Card specification filtering uses exact manifest dimensions; homogeneous hook-card selections use a dedicated physical packing branch, while mixed selections retain the general packer. Why: avoids orientation-based misclassification and preserves existing mixed-layout behavior.
- PC QR reads use authenticated server functions with the handheld role/location and private-object path semantics, without borrowing device credentials. Why: web users have no device token and original QR assets must remain store-isolated.
- Youzan push callbacks: when the Event-Sign header is present, verify MD5(client_id + raw HTTP body + client_secret) only, with no fallback to body.sign. Header-less legacy body.sign messages are read-only hints and stay blocked. Why: only the raw body is covered by the current official signature.
- Youzan member-asset notifications only trigger read-only re-queries into youzan_member_asset_observations. They never write wallets, coupons or the points ledger. Why: the outer fields are unsigned and the ERP is the single ledger.
- Custom print cards (custom_print_cards) are reached only via service_role after handheld device+session and location authorization; AI copy jobs run on the existing listing-image-worker hook with a DB lease/job_token claim, and only super_admin converts custom→preset via a single version-CAS update. Why: keeps store isolation server-side, survives app exit, and makes publish atomic and idempotent.
- Youzan sale stock deduction keys each unit by trade tid + line oid; commit_youzan_sale_line checks exact and reordered legacy positional events under the order lock (ambiguity rejects), counts only processed events as done, and retries failed ones boundedly through commit_sale; the order-sync queue stays order-only, and recovery is only the flag-gated ≤72h keyset-paginated compensation limited to tracked custom single SKUs with location/stock/restock-after-sale/refund guards; trade-push business failures return non-success for platform retry. Why: prevents double deduction across key formats and line reordering, avoids starvation, and keeps standard items and historical imports untouched.
- channel-sync-worker accepts only the service-role Bearer, claims via claim_channel_sync_tasks_v2 (expired-lease reclaim, sku/action canary filters) and finishes only via finish_channel_sync_task with worker fencing; set_stock_zero/delist re-read SKU version, sales_state, is_display, real store inv_stocks and listing ownership before any Youzan write (read failure blocks, active/in-stock/newer tasks are superseded), and dead_letter never closes the sale loop; Tencent systemd timer is the only scheduler. Why: stale sale tasks must not zero or delist items that are back in stock, and a lost lease must not report success.
- Sale-sync release acceptance must check every active branch's unique location/warehouse mapping, recent order scan progress, unfinished tasks, real warehouse stock and branch visibility; verify actual timer API results through the current symlink, not just exit status. A branch with no real custom sale is configuration/read-path verified only, never reported as real-sale accepted. Why: a shared fix or healthy process is not evidence that every store's data path works.
- Store pickup credentials (commerce_pickup_codes) are issued by DB triggers inside the verified-payment transaction, one per store sub-order, and redeemed only through SECURITY DEFINER RPCs that re-check staff store scope, payment/refund/shortage state and readiness under row locks; customer detail exposes credentials only after ownership checks. Why: codes cannot change on payment replay, cannot be redeemed cross-store or after refunds, and UI buttons cannot bypass authorization.
- Staff name/avatar are maintained only by super_admin in PC ERP; canonical source is Auth user_metadata.name + avatar_path in the private staff-avatars bucket (service-role only, no storage policies), signed at read time; handheld/GO/web profile endpoints read live metadata server-side and are read-only. Why: shared accounts see one consistent identity, stale JWTs and expired URLs never become truth, and staff cannot self-edit.
- Bargain-basket (翻筐乐) eligibility is computed only by src/lib/commerce/fankuang.ts from inv_skus.fankuang_override (NULL=auto by price threshold, explicit boolean wins) and only tracked custom single SKUs qualify; storefront filtering runs before paging. Why: one rule for ERP, handheld and storefront, and opted-out items never leak back via price.
- Review demo isolation: src/server/review-isolation.mjs (BOOMER_REVIEW_ISOLATED=true) refuses production data/real channels at boot and blocks external writes. Why: review never touches real systems.
