
## 背景修正

有赞官方文档确认：
- `youzan.shop.authorizedshops.query` **仅限搜狗输入法使用**，普通应用调用会权限拒绝或返回空 `shop_list: []`。
- 其它"连锁门店列表"接口只在连锁版总部账号 + 特定权限包下生效，BOOMER OFF vintage 当前账号不具备。
- 有赞后台**没有"勾选分店授权给应用"这种 UI**，分店天然继承总部授权，但接口侧不开放枚举。

结论：自动拉取分店在你这个账号上**不可能成功**，必须以"手动填 kdt_id"为主流程。

## 改动范围

只动 `/youzan` 路由的"添加分店授权"弹窗 UI 与文案，以及 `youzan.functions.ts` 里相关 serverFn 的职责分工。**不动**任何业务逻辑（同步、库存、订单、调拨、`/store` 移动端）。

## 计划

### 1. 重写"添加分店授权"弹窗

把弹窗主区域从"自动列表 + 兜底输入框"改成**手动输入为唯一主路径**：

- 顶部一段说明：
  > 由于有赞开放平台未对普通应用提供"分店枚举"接口，需要你从有赞后台复制每个分店的 `kdt_id` 后粘贴到下方。系统会用总部 token 逐个验证授权并写入门店库。
- 主体：一个多行 `Textarea`，placeholder 给两种格式样例：
  ```
  187395218 BOOMER OFF vintage（中信泰富店）
  187395218,中信泰富店
  ```
- 解析规则不变：第一段连续 5 位以上数字 → `kdt_id`，剩余部分 → `shop_name`（允许只填 kdt_id，名称为空时回退到验证接口返回的 `shop_name`）。
- 主按钮"验证并添加"：调用现有 `importShopsByKdtIds`，逐个 silent token 验证 → 成功才入 `youzan_shops`，已存在的跳过并提示。
- 结果反馈：toast 显示「新增 X / 已存在 Y / 失败 Z（附原因）」。

### 2. 折叠"尝试自动获取"为次要入口

- 把现有 `listAuthorizedShopsFromHQ` 触发逻辑从"打开弹窗即自动跑"改成默认不跑。
- 在手动区域下方放一个小号链接按钮："尝试从有赞自动获取（多数账号不可用）"，点击后再调用，返回空就显示一行灰字提示，不再当成错误。
- 保留 serverFn 不删，方便未来账号升级到连锁版后还能用。

### 3. 文案与状态收敛

- 移除"未发现已授权分店 / 总部 token 可用但接口没返回"这类容易误导的错误态，统一替换成"请在下方手动添加分店"。
- 总部记录缺失时的提示从开发文案改成："请先在'添加店铺授权'里完成总部（kdt_id=153242272）授权。"

### 4. 不动的部分

- `youzan_shops` 表结构、`importShopsByKdtIds`、`syncYouzanItems`、`syncYouzanOrders`、库存同步、调拨。
- `/store` 移动端、`/shop-mgmt/*` PC 端页面。
- 总部 token / silent token 获取逻辑。

## 验收

- 打开"添加分店授权"弹窗，看到的是手动输入区，而不是 loading + 空状态。
- 粘贴 `187395218 中信泰富店`，点"验证并添加"，成功后列表里出现该分店，状态"已授权"。
- 重复粘贴同一个 kdt_id，提示"已存在，跳过"。
- 粘贴一个不存在 / 未授权的 kdt_id，提示具体失败原因，不写库。
