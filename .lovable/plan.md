## 目标
API 对接页测试失败时，不再把一串英文报错/JSON 甩给用户，而是用一句白话告诉他"为什么失败、下一步怎么办"。原始技术信息保留在折叠区，供排查用。

## 改动范围
只改一个文件：`src/routes/admin.api-integration.tsx` 里的 `ProbeResultBlock`（约 371–420 行）。不动后端、不动数据库、不动接口调用逻辑。

## 具体做法

1. 新增一个纯前端函数 `explainProbeError({ capability_key, method, gw_code, error, response_snippet })`，返回：
   - `title`：一句话结论（例：`有赞暂时拒绝了这次调用（系统异常）`）
   - `reason`：为什么失败（例：`有赞返回了 234000001 系统异常，通常是这个 SPU 在有赞后台被锁定或该店铺零售配置有问题，和我们的参数无关`）
   - `nextStep`：接下来该怎么办（例：`换一个新的测试 SPU 再试；或把 trace_id 发给有赞客服排查`）

2. 覆盖当前常见错误码/关键字，都用中文话术，例如：
   - `gw 234000001 / 系统异常` → 有赞侧临时故障
   - `gw 301000002` / `item not found` → 分店还没上架这个商品，需要先做"总部→分店铺货"
   - `gw 40009 / access_token` / `Unauthorized` → 店铺授权已过期，去门店列表重新绑定
   - `请选择…店铺` / `请填写…` → 参数没填齐，直接提示缺哪个字段
   - `此能力需要用 总部/分店 token` → 换一家对应角色的店铺再测
   - `HTTP 4xx/5xx`（代理层） → 有赞网关不通，稍后重试
   - 兜底：`有赞没有给出明确原因，可展开"技术细节"把 trace_id 交给客服`

3. 失败卡片新版式：
   ```text
   ✗ 测试失败 · 耗时 812 ms
   ────────────────────────────────
   【结论】 有赞暂时拒绝了这次调用（系统异常）
   【原因】 有赞返回 234000001，通常是该 SPU 或该店铺零售配置被锁，和我们发的参数无关。
   【下一步】 换一个新建的测试 SPU 再点一次；如仍失败，把下面的 trace_id 发给有赞客服。
   trace_id: yz7-xxx（一键复制）
   ▸ 技术细节（默认收起：原始 error、response_snippet、request_params）
   ```

4. 成功时保持现有绿色样式与彩带，不改。

5. 顶部 toast 也顺手换：失败时 `toast.error(explain(...).title)`，而不是把原始 `r.error` 丢出去。

## 不做
- 不改 `probeIntegrationCapability` 返回结构。
- 不改任何有赞调用/参数/版本。
- 不动其它页面。
