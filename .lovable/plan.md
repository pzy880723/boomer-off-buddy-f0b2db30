我会把这件事收敛成一个明确目标：系统必须能从已绑定的有赞总部和分店，自动查到并保存「这家分店在有赞链路里到底是谁」，包括店铺授权、门店关系、渠道号、仓库/库位信息；查不到时页面必须用白话告诉你卡在哪一步，而不是让你猜。

## 要实现的结果

1. **门店绑定后自动补全链路信息**
   - 你在门店列表里填入有赞店铺 ID 后，系统会自动：
     - 换取这家店铺的授权；
     - 判断它是总部还是分店；
     - 查询它在连锁体系里的门店关系；
     - 查询可用仓库/库位；
     - 尝试拿到用于铺货的渠道号；
     - 把这些结果保存到门店记录里。

2. **新增一个“检查店铺链路”按钮**
   - 在门店管理或 API 对接页面，对每个分店提供一键检查。
   - 点击后按步骤显示：
     ```text
     1. 分店授权是否可用
     2. 总部授权是否可用
     3. 总部能否看见这家分店
     4. 能否查到门店渠道号
     5. 能否查到仓库/库位
     6. 这家店是否已满足商品铺货和库存同步前置条件
     ```
   - 每一步显示“通过 / 未通过 / 为什么 / 下一步系统会怎么处理”。

3. **把 `youzan.retail.open.warehouse.query` 正式纳入检测**
   - 使用你给的文档页：`https://doc.youzanyun.com/detail/API/0/3365`。
   - 不只测一个版本，会连续测试常见候选版本。
   - 测试结果展示成版本对比：哪个版本通、哪个版本失败、失败原因是什么。

4. **修正当前危险逻辑**
   - 现在代码里有一处逻辑：如果拿不到 `sell_channel_id`，会退回用 `kdt_id` 当渠道号。
   - 这会掩盖真实问题，也是之前反复卡住的原因之一。
   - 我会改成：拿不到渠道号就明确失败，提示“系统已识别分店授权，但没有拿到铺货渠道号”，不再用假值继续同步。

5. **API 对接页面改成“链路检测”视角**
   - 左侧继续用通俗中文说明“这个能力解决什么业务问题”。
   - 右侧不仅能测单个接口，还能一键跑完整链路。
   - 失败结果翻译成自然语言，例如：
     - “总部授权可用，但总部接口没有返回这家分店”；
     - “分店授权可用，但仓库接口这个版本不支持”；
     - “已经查到门店，但没有拿到铺货渠道号，商品暂时不能自动发布到这家店”。

## 数据库调整

会给 `youzan_shops` 增加用于保存链路结果的字段，例如：

```text
sell_channel_id       铺货用渠道号
warehouse_code        默认仓库/库位编码
warehouse_name        默认仓库/库位名称
chain_probe_status    最近一次链路检测状态
chain_probe_result    最近一次链路检测的完整结构化结果
chain_probe_at        最近一次检测时间
```

这样系统不用每次都重新猜，后续铺货和库存同步直接读取已确认的链路信息。

## 代码调整范围

1. **后端能力检测**
   - 扩展 API registry，把仓库查询、门店关系查询、渠道查询加入正式能力表。
   - 增加多版本检测函数，不再只测单个版本。
   - 新增完整店铺链路检查函数。

2. **门店绑定逻辑**
   - 新增/绑定门店后，自动触发一次链路检查。
   - 成功则显示“已绑定 + 链路已通过”。
   - 失败则显示“已绑定，但链路未完整”，并说明卡在哪一步。

3. **铺货链路**
   - `ensureBranchDistribution` 改为优先使用已保存的 `sell_channel_id`。
   - 如果没有 `sell_channel_id`，先自动跑链路检查。
   - 仍然拿不到就停止，不再用 `kdt_id` 假装渠道号。

4. **前端展示**
   - API 对接页增加“一键检查店铺链路”。
   - 门店卡片显示：授权状态、链路状态、渠道号、仓库/库位。
   - 技术接口名继续收进“技术信息”，默认给你看业务结果。

## 验收标准

完成后我会用当前已绑定的中信泰富分店实际跑一遍，必须给出清楚结果：

```text
中信泰富分店
- 授权：通过 / 未通过
- 总部是否能识别该分店：通过 / 未通过
- 铺货渠道号：已拿到 / 未拿到
- 仓库/库位：已拿到 / 未拿到
- 是否可以继续做 SPU 铺货 + 库存同步：可以 / 不可以
- 如果不可以：明确是哪一步不满足
```

如果链路检测通过，再继续测试商品从总部铺到中信泰富分店并同步库存；如果检测不通过，先把失败点定位到具体接口和原因。
