
## 我先把现在的实情摆清楚

我进后台看了你的数据，问题不是"权限没开"这一个原因，是三件事叠在一起卡住了：

1. **"有赞默认分组"设置里还是空的**（数据库里 `youzan_hq_default_category_id = null`）。
   - 只要这里空着，任何自定义商品往有赞推的第一步就会被我们自己挡住："尚未配置有赞默认商品分组"。
   - 你之前那两个测试商品报的 `[gw 4005] 非法的API`，是更早一次尝试留下的旧错误，那时候我们还会硬着头皮往有赞发，被有赞的网关拒了。

2. **那两条失败任务已经退到最长等待期（attempts=6）**，队列自己排到 24 小时后才会再跑一次，所以你现在点重推也感觉"没反应"。

3. **`[gw 4005] 非法的API` 这个错，98% 是有赞开放平台"应用"里勾选的接口范围没包含 `retail.open.spu.create.3.0.0`**。
   - 你说的"权限都开了"，一般是指店铺 → 授权我们的应用；但真正决定能不能调这个接口的是应用本身的"授权 API 范围"清单。这两件事是分开的，很多人踩过。

## 我打算这么改（都是页面上能直接看到的东西，不动业务规则）

### 1. 在"设置 → 集成"的体检里，把这三件事分成三行显式判定
- 默认分组：有 / 没有；没有就给一个 **"去选一个"** 的按钮直接滚到分组选择器。
- 总部 / 门店授权：能不能 `youzan.shop.get`，不能就写"总部授权失效，请重新授权"。
- 推商品接口：真的用总部 token 打一次 `retail.open.spu.create` 的空请求：
  - 返回"参数缺失"→ 说明接口通了（正常）。
  - 返回 `4005 / 非法的API` → 明确写「**这是"应用授权 API 范围"里没勾 `零售·SPU 创建 3.0.0`；请到有赞开放平台 → 我的应用 → 授权接口范围里加上，然后重新授权店铺**」。
  - 其他错 → 原样翻译。

### 2. 门店商品页 → 顶部加一条"同步状态"提示条
- 检测到默认分组为空 → 红色横条："还没选默认分组，自定义商品推不上有赞。点这里去设置。"
- 检测到有 `status=error` 的 branch_stock 链接 → 黄色横条："有 N 个自定义商品推送失败，点这里查看原因 / 一键重推。"

### 3. "一键重推"真的能立刻跑
- 现在的按钮把 `youzan_stock_sync_queue` 里对应的 `failed` 任务 `attempts` 清 0、`next_run_at` 设为当下，`status` 设 `pending`；同时把对应 link 的 `status` 从 `error` 回 `pending`，然后现场跑一次 worker，把结果（成功 / 失败原因）直接 toast 出来，不要再让用户猜。

### 4. 新建/编辑自定义商品的时候提前拦一次
- 保存自定义 SKU（`sku_scope=custom`）时，如果默认分组为空，弹一个 dialog："想同步到有赞的话得先选一个默认分组，要现在去设吗？"—— 用户可以选"以后再说"，SKU 还是照存，只是不入队推有赞，避免又产生一批 4005 死信。

### 5. 顺手做的两件小事
- 把当前那两条卡死的记录（`test`、`测试商品`）在这次改动里自动 reset 一次，让你能马上看到"如果默认分组设好 + 接口范围勾好，它们会怎么走"。
- `explainYouzanError` 里补一条：识别 `4005 / 非法的API` 时，把提示改成上面第 1 点里那段话（提到具体接口名 + 授权范围 + 需要重新授权店铺），而不是笼统的一句"有赞拒绝"。
