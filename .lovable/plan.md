## 现在的问题
1. **商品名为空**：有赞 `youzan.retail.open.spu.query.3.0.0` 返回的 SPU 实际把名字放在 `product_name`、图片放在 `photo_url[0].url`，我们之前只读 `title/name/spu_name` 和 `pic_url/main_pic`，全部没命中。
2. **"门店"列没意义**：因为同一个商品总部 + 每家分店各占一行，列表里会重复出现，看起来杂乱。
3. **缺"在售门店"信息**：总部 SPU 接口返回的 `sell_channels` 只是渠道类型代码（如 `[2,4]` = 网店/门店），不是具体哪些分店。要拿"哪些门店在售这件商品"，需要分店维度的"在售 SPU 列表"接口；之前用的 `youzan.retail.open.online.spu.query.1.0.0` 当前报 `[gw 4005] 非法的API` —— 说明这条 API 没在你有赞云应用里订阅，需要先去应用能力包里加上才能拉到真实的"在售门店"。

## 调整方案

### 1. 修同步逻辑（立即生效，重新同步一次即可）
- `normalizeSpuRow` 增加字段：
  - `title`: 优先 `product_name`，再 `title/name/spu_name`
  - `pic_url`: 优先 `photo_url[0].url`，再 `pic_urls/images/...`
  - `is_listed`: 根据 SPU 状态字段（`status` / `online_status` 之类）落库
- 重新跑一次"总部同步"，所有商品的名字、缩略图、状态都会回填。

### 2. 重做"门店商品库"列表（UI 层 + 一支聚合 serverFn）
- 默认展示总部 SPU 列表（每个商品只占一行），不再按 `kdt_id` 平铺。
- 列：商品 / 价格 / 总库存（汇总所有分店）/ **在售门店**（chip 一排显示分店名）/ 状态 / 操作。
- 删掉"门店"列。
- "在售门店" 数据来源：
  - 如果已经能调到 `youzan.retail.open.online.spu.query.1.0.0` → 按真实分店在售列表显示。
  - 如果还是 4005 → 退化为"等待获取分店在售数据"占位提示，并在页面上方贴一个"需要在有赞云应用里订阅『网店在售商品查询』能力包"的提示卡。

### 3. 状态徽标改 3 色
- 🟢 绿：在售 + 总库存 > 阈值
- 🟠 橙：在售 + 总库存 ≤ 库存预警值（默认 3，可后面做配置）
- 🔴 红：已下架 或 总库存 = 0

### 4. 操作列保持不动
"调入 / 调出" 按钮逻辑不变。
