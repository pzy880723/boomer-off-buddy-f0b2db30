## 原因与修复

- 有赞订单同步任务原本只保存订单，不扣库存。这是防止历史订单导入误扣的保护，但缺少可靠的近期漏单补偿。
- 渠道清零/下架队列原来的定时调用指向 Lovable，鉴权和腾讯固定出口执行要求不一致，任务积压。该旧定时任务已停用，改由腾讯执行。
- SKU 编码与大类编码混合匹配会匹配多个价位，阻断整单后续处理。现在优先使用具体 SKU 的编码与条码，拒绝不明确的映射，不猜商品。
- 新天地启用了有赞进出存单据库存，普通 quantity.update 返回“修改库存不会生效”。渠道队列现已复用既有单据库存路径，并回读仓库库存。已下架且仓库已为 0 的商品可只读确认完成，不重新铺货。
- 推送补拉最新订单失败时不再降级使用旧事件扣库存，返回失败供重试；已退款订单/商品行不再扣库存。
- 每单位使用订单行稳定键，兼容旧键；已处理事件重复送达不重复扣，失败事件可有界重试。
- 清零/下架前复核真实门店库存、库存版本、展示状态、渠道归属和任务租约。补货后过时的任务作废，不清零新库存。

- 推送及时到达时按最新订单处理；漏推送通过订单拉取和定时补偿兜底，属于分钟级修复，不保证第三方接口永不故障或所有通知即时到达。
