# 线上订单退款状态修复验收

日期：2026-09-24

## 原因

普通商户退款回写已经更新付款状态和退款账本，但没有同步关闭订单生命周期。ERP 列表又只按订单状态显示，导致全额退款后仍显示“履约中”。手持订单的关闭状态也会被误标成“已取消”。

## 已完成

- 全额成功退款按订单总额、全部有效付款与成功退款账本核对后关闭订单，记录审计；部分退款不关闭整单。
- 拦截全退后继续拣货、新建发货记录；保留已存在的发货历史。并发检查使用订单行锁。
- 统一“线上订单”入口、标题和相关链接，增加“已退款”筛选；退款状态优先于旧履约状态。
- 线上列表排除门店 POS 单；已取消的未付款单不计入运营中心“待付款”。
- 增加来源记录与标签，支持小程序、APP、网页；外卖保留展示口径，未开通外卖渠道导入。
- 创建订单可提交可选 source_platform；幂等重试不覆盖首次来源。缺失来源不猜填。
- 页面自动刷新与手动刷新；失败时明确提示，不冒充空列表。

## 数据验收

只读核对当前 4 笔商业订单，其中线上订单 3 笔、POS 订单 1 笔。全额退款 1 笔，成功退款记录仍为 1 笔；状态回填审计 1 条，来源回填审计 1 条。其余两笔历史取消单保留“来源未记录”。

没有重新发起退款、发送短信、修改库存或覆盖历史发货记录。

## 验证证据

- Codex：74 项回归测试通过，覆盖全退/部分退款/退款中、来源、列表与详情状态、支付退款幂等、客户订单隔离。
- Codex：合入数据库主线前后 TypeScript 全量检查均通过。
- Lovable 内嵌数据库：增量迁移 0007、0009、0010 已应用；其隔离 SQL 用例 01–07 与 4 个并发脚本通过。Codex复核迁移与测试代码，并独立执行生产只读账本验证。
- 腾讯云构建通过，登录 hydration、无认证 API 拦截、设备无员工登录拦截、云端标签模板读取均通过。
- 实际登录页面验收：标题和侧栏为“线上订单”；“已退款”筛选为 1 单；“待履约”为 0 单；退款单显示“小程序”“已退款”“停止履约”；全列表 3 单，不再混入 POS。
- 11 个上线源码文件逐一比对 SHA-256，与审核补丁一致。未打包客户资料或密钥。

## 边界

本次不代表已接通新的外卖平台、全网发布或新增分店自动分单算法；没有以真实客户订单做再次扣款、退款或发货测试。现有商品库存与门店分配逻辑保持不变。后续新渠道应接入统一订单、库存和门店履约体系，并独立验证外部订单幂等与跨门店隔离。
