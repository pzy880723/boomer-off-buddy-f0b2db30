# 有赞图片与库存同步修复验收

日期：2026-09-27。生产：`https://erp.boomeroff.com`。

## 本次问题与原因

1. 首次上架使用原图，AI 修图完成后没有可靠的有赞换图任务，门店会一直保留首次上架的原图。
2. 部分 AI PNG 超过有赞素材上传限制；旧代码上传失败后回退到源地址，掩盖了同步失败。生产启动环境还缺少明确的腾讯媒体域名。
3. 旧 Lovable 预览站定时库存任务仍在运行，使用过时的商品 ID 解析，把商品库 ID、渠道商品 ID、规格 ID 混用，造成有赞报“商品不存在”。
4. 库存重试以前使用会随领取变化的时间戳作幂等标识，且迟到的旧任务可能覆盖新任务结果。

## 已发布修复

- AI 图片变化、门店发布完成均事务性登记图片同步任务；按版本和租约领取，失败重试，完成前回读总部和目标门店全部图片。
- 只对有赞上传副本压缩，保留 ERP 原图与 AI 源图；上传失败显式失败，不再静默使用原图地址。
- 以总部编码、指定门店和线下渠道精确解析商品与规格，发布后保存回读取得的 ID；标准商品仍按对应条码定位规格。
- 库存操作使用稳定 UUID，重试不重复生成业务操作；结束任务使用版本条件，不能覆盖新请求。
- 关闭旧预览站 cron job 2；启用腾讯固定出口的鉴权库存与图片 worker。候选端口禁止执行 worker。
