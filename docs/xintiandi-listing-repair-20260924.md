# 新天地拍照上架修复验收

## 已确认的故障

- ERP 两条商品各有新天地库位库存 1；旧 `inv_skus.stock_qty=0` 不是该库位的库存。门店列表另有 448 个 SKU 一次查询导致请求头过大、错误被显示为空列表的问题。
- 有赞发布参数混用了元/分；总部受控价格还需要使用商品库 ID 和总部规格 ID 更新。新天地价格下发有延迟，必须回读确认。
- 有赞开启进出存单据管理，普通改库存接口返回内层 `success:false`，旧逻辑却当成成功。
- 商品库 ID、总部渠道 ID、分店渠道 ID 被混用；同名查找又把不同 ERP SKU 关联到同一商品。条码应来自 ERP `barcode`，不能用平台生成码替代。
- iOS 标签栅格高度未扣除打印起始偏移，内容可能越过当前标签的可打印范围，引起定位跳纸。

## 本次变更

- 自定义商品按稳定编码匹配，取消同名兜底；回读门店渠道 ID、价格和收银条码，核验后才记录同步成功。
- 只向实际库存库位对应门店发布；撤销非目标分店渠道，不删除共享总部商品。
- 单据管理门店改走映射仓库的绝对库存调整，并回读；保留幂等操作号，后续补货使用队列的新版本。
- 门店商品、关联、封面查询按 100 个 SKU 分批；切店不展示上一门店数据；加载失败不再伪装为零库存。
- 门店商品操作菜单增加删除确认。删除由总部权限的事务 RPC 执行；有库存、流水、订单或渠道关联的商品不能硬删除。本次没有删除真实商品。
- iOS 打印保持黑标/间隙定位及打印后一次 `1D 0C`；扣除起始偏移再约束图片高度，避免向上取整多出一个点。
