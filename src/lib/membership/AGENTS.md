# Membership rules
- Newcomer coupon pack: versioned slots + durable per-slot jobs (commerce_newcomer_*); Youzan is the only authority, success needs a Youzan coupon id, unknown results are reconcile-only (never resent, not_found stays unknown); one grant per customer and per phone hash; all switches default off. Why: no double issue, no fake local coupons.
- Auto-enroll: DB trigger on commerce_customers (insert / phone first verified) + bounded commerce_newcomer_backfill; conflicts never merge; enroll failures only WARN, never block signup. Trusted mapping missing/unavailable is a bounded retry (waits for member-sync), never permanent blocked; mapping conflict stays blocked. Points projection is never an identity source. Why: enrollment must not depend on the user opening the member code, and identity must come only from the trusted mapping store.
- Youzan contract (doc4485, verified via Tencent fixed egress): send/3.0.2 takes activity_id + yz_open_id + requestId + verify_code; real coupon id is only data.voucher_identity.coupon_id (never verify_code); voucher.query/3.0.0 pages data to total and matches yz_open_id+activity_id+verify_code exactly. verify_code = 'ncv' + sha256(request_key)[:12], identical in TS deriveVerifyCode and SQL commerce_newcomer_verify_code. Why: precise reconcile, no cross-slot coupon substitution.
- Success requires a verified provider receipt: commerce_newcomer_finish_success (distinct RPC, no defaults) validates coupon_id + provider verify_code + real valid_start/end + amount/threshold/activity against slot rules and writes the pos_customer_coupons Youzan mirror in the same transaction (unique (external_provider, external_id) rejects cross-slot duplicates, mirror failure rolls back the slot); the legacy 5-arg finish rejects receipt-less success as receipt_required. enroll is fail-closed: mainland phone regex, external_subject, unique active phone, and a complete version (8 slots, 10000 fen, all templates bound, 90 days). Slot rules are immutable once a version has grants; mirror status sync (NEWCOMER_MIRROR_SYNC_ENABLED, default off) is read-only on Youzan and only moves mirrors out of active. Why: no fake success, no synthetic dates, no rule swap; points projection/ledger/wallet are never touched.
- Worker scope + mirror sync (0093): worker claims only via commerce_newcomer_claim_scoped and backfill only via commerce_newcomer_backfill_scoped with the canary UUID list (NULL only when ALL_CUSTOMERS=true; empty list = do nothing). Member-mapping missing/exception: dispatch → retry, reconcile → stays unknown. voucher.query uses page_num + activity_type_group=1 + status=0, response is top-level data array + top-level total; numeric status 1 active/2 frozen/3 used/4,5 void. Mirror sync rotates by provider_status_checked_at (stamped every check), applies only via commerce_youzan_mirror_apply_status (external_id must match, frozen↔active reversible, terminal never rewritten). Why: no starvation, no wrong-slot status, no queue pollution outside canary.
